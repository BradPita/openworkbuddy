# 账号与部署运维

写给要把 OpenWorkBuddy 放到服务器上、给别人开账号的那个人。按「装好 → 开第一个号 → 加人 → 出事了怎么办 → 备份升级」的顺序排，出了什么事翻到对应那节就行。

角色和权限的来龙去脉在 [多人一起用](多人协作.md)，部署命令和反代在 [deploy/README.md](../deploy/README.md)。这里只讲**日常怎么维护**。

## 先挑一种部署方式

| 你的情况 | 怎么部署 | 账号这层 |
| --- | --- | --- |
| 就自己用 | 装桌面版 | 一个账号，什么都不用管 |
| 一个团队共用 | 一台服务器，`bash deploy.sh --domain 你的域名` | 所有人在默认组织里，管理员管人 |
| 给几家公司分别用 | 同一台服务器，平台超管给每家开一个组织 | 每家的成果目录、会话、账号、席位、账单、审计各是各的，见「一台服务器带几家组织」 |
| 几家之间要硬隔离，还要让 agent 跑命令 | 一家一个实例（一家一个容器或一台机器） | 各自一套，互不相干 |

第三行和第四行的差别只有一条：**命令行**。开着命令行的 agent 在这台机器上跑 shell，应用层那道墙挡不住它。所以同一台机器上的租户组织默认关着命令行；哪家非要跑命令，就给它单独一个实例。

## 第一个账号

服务起来之后**马上**打开地址注册。第一个注册的人就是平台超级管理员，也就是这台机器的主人：能改模型 Key、技能、连接器、定时任务，能开新组织。空库挂在公网上，谁先打开谁就是它。

注册完之后，默认不再允许别人自己注册。接着做两件事：

1. 填模型 Key（界面会引导，填完当场发一条真请求验活）。
2. 进企业后台 →「客户端安全」，按下面「上线前自查」把闸门过一遍。

## 加人

三条路，推荐从上往下挑：

1. **直接建号**：企业后台 →「成员与部门」→ 添加成员。随机密码只显示这一次，发给本人，让本人登录后自己改。
2. **邀请码**：同一页生成。能限次数（1–1000）、设有效天数（1–365，默认 7 天）、预先写好角色和部门。撤销只影响还没用掉的。码上能写的角色，跟你自己能授的一样：管理员发不出管理员的码，谁也发不出超管的码。
3. **开放注册**：「基础设置」里打开。挂在公网上时，同时打开「注册后需要审核」，自助进来的人先挂成待审核，要管理员在「成员审核」里点头才能用。拉完人记得关掉。

一个部门会进好几个人的话，先给部门存一个**权限模板**（默认角色、默认月额度），之后在这个部门开号时角色和额度留空，就会自动套上模板。模板只管之后进来的人，不会动已有的账号。

**席位**：停用的人不占席位，待审核的占。席位满了，建号、邀请码注册、把停用的人重新启用，这三条路都会被拦下，并提示先加席位。

## 有人离职

成员那一行点 **办离职**，一次关掉：账号、这个人所有设备上的登录、名下的定时任务、发出去还没用完的邀请码、名下的中转站 Key（用这些 Key 的程序下一次调用就报 401，先通知对接的人）、二次验证，以及正在跑的任务。**不删数据**：对话、成果、用量、审计原样留着。

- 弹窗里可以把这个人的定时任务交给别人。接手的必须是本组织在用的人；交过去的任务**仍然关着**，接手的人看清楚之后自己打开。
- 办完出一张纯文本回执，可以直接贴进交接单。
- 删掉的账号，登录名不能再给别人用；留下的对话仍归原来的组织。
- 同一个人回来了：在成员那一行点「改」，把状态改回「正常」（席位满了会拦下）。

## 密码或二次验证丢了

**成员、管理员**：找档次更高的人在「成员与部门」里点那一行的 **重置密码**（新密码只显示一次）；手机丢了点 **解二次验证**（开了二次验证的人那一行才有）。只能管档次比自己低的人，同级之间谁也动不了谁：成员找管理员，管理员找超管。

**超管自己**（上面没有更高一档的人了，尤其是平台超管）：到服务器本机上跑命令行。能登上这台机器的人本来就是机主，这条路**不接到网页上**。

```bash
openworkbuddy passwd <用户名>              # 随机生成一串新密码，只显示这一次
openworkbuddy passwd <用户名> '新密码'     # 自己定
openworkbuddy 2fa <用户名>                 # 看开没开二次验证、还剩几个恢复码
openworkbuddy 2fa <用户名> --off           # 关掉，登进去之后重新绑
openworkbuddy owner                        # 看每个组织现在的超管是谁
openworkbuddy owner <用户名>               # 把超管换成这个人，原来那个改任管理员
```

改完密码，这个人在别处的登录全部作废。

用 Docker 部署的，在容器里跑：

```bash
docker exec -it openworkbuddy node cli.js passwd <用户名>
```

用 systemd 或 PM2 直接跑的，进代码目录，带上跟服务**同一个** `OPENWORKBUDDY_HOME`：

```bash
OPENWORKBUDDY_HOME=/你的/数据目录 node cli.js passwd <用户名>
```

少了这个变量，多半会报「找不到 config.json」，别照它说的去跑 npm start；万一代码目录里也有一份，改的就是那一份，服务那边什么都没变。

## 出了事去哪查

| 想知道 | 去哪看 |
| --- | --- |
| 谁在什么时候登录、登录失败 | `logs/app-<年-月-日>.jsonl`，留 14 天 |
| 谁被锁了、停用的账号还在试着登 | 企业后台 →「操作审计」（文件是 `data/audit/<组织 ID>.jsonl`，默认组织就是 `default.jsonl`；每个组织最多留 5000 条） |
| 谁加了人、改了角色、发了码、办了离职 | 同上，「操作审计」 |
| 命令审批、删文件拦截这些安全事件 | `data/audit.json`，只留最近 1000 条 |
| 每一次任务花了多少 | 企业后台 →「用量明细」，能按时间、按人筛；导出一次只导当前这一页（50 条） |

登录限流：同一个账号 15 分钟内错满 8 次，或者同一个 IP 错满 30 次，就锁到这 15 分钟过完为止。只记在内存里，重启就清。前面挂了反代的，记得设 `OPENWORKBUDDY_TRUST_PROXY`（见 deploy/README.md），不然全公司共用一个 IP，一起被锁。

## 备份、恢复、升级

**备份**：平台超管在 设置 →「数据」→「数据备份与恢复」里点立即备份，或者设成每天、每周自动备。包里有账号、组织、会话、记忆、定时任务、自己写的技能、后来新建的组织的成果目录，还有 `config.json`（**含明文 API Key**，别往云盘和仓库里放）。

**不在包里**：默认组织的成果目录 `workspace/`。它太大，自己拷。Docker 部署最省事的做法是整个 `openworkbuddy-data` 目录打包带走，连 `workspace/` 一起：

```bash
tar -czf openworkbuddy-data.tar.gz openworkbuddy-data
```

**恢复**：同一个面板的备份列表里，点那一份后面的「恢复」。从别的机器带来的包，先点「导入备份文件」传上来，再点「恢复」——光导入不生效。恢复前会自动把现状备一份，恢复完要重启。

**升级**：先备份，再升级。

```bash
bash deploy.sh --update     # Docker：拉代码、重建、重启，数据目录不动
```

systemd 的升级命令在 deploy/README.md 里。每个版本改了什么看 [CHANGELOG](../CHANGELOG.md)。

哪些文件在哪、搬机器怎么搬，见 [数据同步与搬家](数据同步与搬家.md)。

## 商业授权

个人非商用免费。公司用、个人拿来做商业用途，都要买授权；公司可以先试用 30 天。

买到的授权码填在企业后台 →「商业授权」。它在这台机器上**离线**验过就算数，不联网，也不会因为到期把谁锁在门外：到期了界面上标红，换上新码就行。授权条款见 [COMMERCIAL-LICENSE.md](../COMMERCIAL-LICENSE.md)，购买发邮件到 contact@aijentra.com。

## 一台服务器带几家组织

只有平台超管能做，入口是企业后台 →「组织管理」。

**开一家新组织：**

1. 点 新建，填组织名（40 字以内，不能重名）、套餐、席位上限、到期时间（留空 = 长期）。
2. 在它那一行点 **邀请**，发出第一张码。默认是管理员、一次有效、7 天。拿这张码注册的人就是这家的超管。
3. 之后这家自己加人、发码、审核、办离职。每家最多存 200 张邀请码，超了最旧的自动清掉，不会挤掉别家的。

**这家的东西放在哪**：成果目录在 `data/tenants/<组织id>/`，默认组织的人看不到，反过来也一样。会话、账号、席位、用量、审计都按组织分开。

**这家自己改不了的**，要平台超管在「组织管理」→ 改 里设：

- 套餐、席位上限、到期时间
- 允许运行命令行（新组织默认关；组织管理员关得掉、打不开）
- 记账折扣、中转每月封顶（组织管理员改不了，调紧调松都不行）

**不分组织、全服务器一份的**：模型和 Key、技能、专家、MCP 连接器、共享记忆、备份。这些只有平台管理员能改，租户的人读到的 Key 是空的，连接器的地址和启动参数也看不到。

定时任务另算：设置里那张定时任务表只有平台管理员进得去，但每个人都能在对话里让 agent 给自己排（本人点同意才排上），任务记在本人和本人的组织名下。

**到期了会怎样**：这家的人发不起新任务，网页、IM、定时任务、中转 Key 全停；登录、翻历史、下载成果照常。这家的定时任务会被关掉并写明原因，续期后**不会自己打开**，得有人去点。

**想立刻停掉一家**：把到期时间改成今天以前。

## 上线前自查

- [ ] 第一个账号是自己注册的
- [ ] 开放注册是关的；要开，同时打开「注册后需要审核」
- [ ] 服务只绑在 127.0.0.1，外面走反代 + HTTPS（`deploy.sh --domain` 会配好）
- [ ] 挂了反代的，设了 `OPENWORKBUDDY_TRUST_PROXY`
- [ ] 设置 → 安全：「安全网关」和「删除保护」都开着（默认就是开的）
- [ ] 用不着命令行的组织，命令行是关的
- [ ] 「客户端安全」里按需设了密码最短位数、复杂度、强制二次验证（**先绑好自己再开强制**）
- [ ] 自动备份开了，而且真从一个备份恢复过一次
- [ ] `openworkbuddy-data/config.json` 不在任何云盘、仓库、镜像里
- [ ] 会用 `openworkbuddy passwd` 和 `openworkbuddy owner`，别等丢了钥匙那天才查

## 额度和预算（多人共用一把 Key 时才开）

- **余额闸门**：默认关，关着只记账不拦人。在「计量设置」里打开「余额扣完就不让跑」，可用余额为 0 的人就发不出任务。一个人自己用别开，拦的只是你自己。
- **月预算（元）**：在「API 中转站」页设组织每月封顶和人均默认上限，也能给某个人单独设。超了之后网页上发任务、定时任务、中转 Key 都会被拦，不只是中转；每月 1 号重置。租户组织的每月封顶只有平台超管能在「组织管理」→ 改 里设，人均默认和个人上限组织管理员自己能设。
- 用量流水跟这两个开关无关，一直照记。

## 现在还做不到的

- **组织删不掉**。要停一家，就把到期时间改到以前。
- **同一个组织的人共用一个成果目录**，互相看得见产出。要分开，就分成不同组织，或者分成不同实例。
- **开了命令行的租户能碰到别家的目录**。所以新组织默认关着命令行，要开只能找平台超管。
- **升级上来的老会话没记归属**，一律算在平台超管名下：同组织的管理员也看得到，普通成员看不到。
- **租户组织的付费 API 额度**界面上还设不了，现在只能给默认组织设。
- **飞书 / 微信这些渠道进来的任务记在平台超管名下**，不分是谁发的。
- 登录限流只在内存里，重启清零。
