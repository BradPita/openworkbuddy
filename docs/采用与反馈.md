# 从看到项目到首次成功

[English](#english) · [返回 README](../README.md#quick-start)

## 成功路径

README 第一屏解释产品、适用用户与交付物；点击快速开始，安装、连接模型，再用 [同一份任务](../examples/quick-start/task.md) 生成 `project-update.pptx`。打开实际文件，核对输入事实，继续要求一次修改。

首次成功要求同时满足：文件存在且非空、能打开、四页内容与输入一致且文字可编辑、后续修改落到同一份文件。安装成功、聊天回复“完成”或 Star 都不能代替这些条件。

## 先做一次不提供帮助的试用

请一位没有参与开发的人试用；这是人工验证流程，当前没有声称已经邀请或完成。

1. 只给 README 的第一屏，问他产品是什么、给谁用、能得到什么。
2. 给快速开始链接，让他独立操作，不提前解释模型、文件路径或权限。
3. 记录他在哪一步停止、错误原文、是否需要帮助，以及第一次打开可用结果的时刻。
4. 用统一核对标准检查 `project-update.pptx`，再让他做一次修改。
5. 经他同意，七天后确认是否再次完成过有实际用途的任务。

记录下载、启动、模型配置、任务提交、结果打开与核对完成的相对秒数。**首次成功耗时 = 核对完成 − 开始安装；模型准备好之后的任务耗时另算。**不要通过加速演示估计实际耗时。三秒看懂、三分钟成功都是设计检查目标，当前没有公开实測数据或承诺所有环境都能达到。

## 简单漏斗与缺失项

| 阶段 | 定义与数据来源 | 当前采集状态 |
|---|---|---|
| 官网访问 | 访问项目官网；如未来接入统计，使用聚合计数 | 缺失；当前页面没有访问统计脚本 |
| 仓库访问 | GitHub 仓库管理页面的聚合访问量、来源 | 尚未导出；公开 Star 不能替代访问量 |
| 安装 / 启动 | 试用者实际完成安装、打开应用 | 仅人工试用记录；没有自动遥测 |
| 模型可用 | 测试连接通过，或本机引擎已能执行 | 仅本机状态；没有跨安装汇总 |
| 首次任务提交 | 提交统一 PPT 任务 | 仅本机任务记录；没有跨安装汇总 |
| 首次成功 | 实际文件通过上面的四项核对 | 需人工核对；当前缺失 |
| D7 复用 | 首次成功满七天的人，在七天内又完成过实际任务 | 需自愿回访；当前缺失 |
| 合格反馈 | 带环境、操作步骤、预期和实际结果的可复现反馈 | 人工分类；当前缺失 |

分母保持一致：首次成功率用同一批**开始试用的人**，不要只统计任务已经提交的人；也可另报“已提交任务中的成功率”，但需要写清分母。D7 复用率只统计已满七天的首次成功者。按版本、入口方向和试用批次看变化，不能把互不相同的人群拼成一条可计算的转化率。

[聚合记录模板](adoption-metrics.csv) 只有列名，没有虚构数据。未采集的单元格留空，并在说明中标记缺失。公开报告只包含汇总数字，不包含用户名、邮箱、Key、文件正文或原始执行记录。CLI 的安装和复用不能可靠识别时，继续标缺失。

## 双向链接怎么区分

- README → 官网：`utm_source=github&utm_medium=readme&utm_campaign=first_result`。
- 官网 → GitHub：`utm_source=website&utm_medium=referral&utm_campaign=first_result`。

这些参数仅标识入口方向。**添加来源参数本身不会生成统计数据**；GitHub 的来源统计也不等于完整的逐人安装漏斗。当前没有增加第三方遥测、用户标识或自动上传。

Star 用于收藏项目，Watch → Custom → Releases 用于接收发布通知。Star 可以作为传播的补充指标，不能用来估算激活或复用。

## English

The first-success path is: understand the product → install and launch → connect a working model → submit the [standard project update deck task](../examples/quick-start/task.en.md) → open `project-update.pptx` → check the supplied facts → request a change to the same file.

Ask a person who did not build the app to follow the README without coaching. Record relative times for download, launch, model setup, submission, opening the result and completing review. First-success time starts when installation begins; report task time after model readiness separately. Three seconds and three minutes are design targets. No first-success time or rate has been published, and an accelerated demo is not timing evidence.

Success requires a nonempty file on disk, a working preview, four editable slides matching the supplied facts, and a follow-up that changes the same file. Installation, a “done” reply and Stars are separate signals.

The [aggregate CSV template](adoption-metrics.csv) has no fabricated observations. Website visits, installation totals, cross-install first success and D7 reuse are currently missing. GitHub traffic can be exported by a repository administrator, but has not been collected for this report. Local task records are not a cross-install funnel. Unknown CLI behavior remains missing.

Use the same cohort as the denominator, include unsuccessful trials, and only include people who have reached day seven in D7 reuse. A qualified issue provides environment, reproduction steps, expected behavior and observed behavior. Publish aggregate numbers only; exclude account names, emails, secrets, document contents and raw traces.

README → website links use `utm_source=github&utm_medium=readme&utm_campaign=first_result`; website → GitHub links use `utm_source=website&utm_medium=referral&utm_campaign=first_result`. These labels do not collect events by themselves. No telemetry, user identifier or automatic upload was added. Star bookmarks the repository; Watch → Custom → Releases subscribes to releases.
