# OpenWorkBuddy 授权码核验清单

给买了授权的单位、以及让供应商出示授权码的甲方用。整套做完大约 5 分钟。

## 先准备

- 授权码：`OWB1.` 开头的一整串，要复制完整
- 你们单位的全称，按营业执照写
- 实际要用这套软件的人数
- 实际用法：自己内部用、对外提供服务、给客户交付，还是打包分发

## 一、确认核验工具本身可信

1. **公钥逐字比对。** 打开官方仓库 github.com/CatCatUncle/openworkbuddy 里的 `src/domains/account/license.js`，找到 `PUBLIC_KEYS` 那一行。把核验页上「本页用来验签的公钥」和它逐字对一遍。对不上就别用这个页面，改用第二步的命令行。
2. **页面离线打开。** 双击 `index.html`，或者拖进浏览器就行，不用联网。页面里没有外部脚本，安全策略也禁止它发任何网络请求，你粘贴的授权码不会离开这台电脑。

> 不要只拿这份清单比公钥：清单和页面可能是同一个人改过的，以官方仓库为准。

## 二、验真伪（任选一种，都做更稳）

- **核验页**：把授权码粘进去，点「核验」。在 Chrome 154 上实测过；浏览器太旧会提示「不支持 Ed25519」，那就换新版浏览器，或者用命令行。
- **命令行**：克隆官方仓库，在仓库目录里运行 `node scripts/issue-src/domains/account/license.js verify "OWB1.……"`。它用仓库自带的 `src/domains/account/license.js`，和核验页互不依赖。
- **管理后台**：在软件的「商业授权」页填进去。

看结果：

| 颜色 | 意思 | 下一步 |
|---|---|---|
| 绿：真码，在有效期内 | 作者签发，内容没被改过 | 继续第三步 |
| 黄：真码，但已过期 | 作者签发，但过了到期日 | 找作者续期 |
| 红：没有验过 | 不是作者签发、被改过，或者没复制完整 | 先重新完整复制一次；还是红就停下，问供应商或作者 |

## 三、逐项对照（验过真伪只说明码是真的，不说明是给你们的）

1. **授权给** = 你们单位全称。核验页上可以填全称自动比对，空格、全半角、大小写不计。名字不是你们的，这张码就不是给你们的。
2. **使用范围**要覆盖实际用法。供应商用它给你们交付的，范围要包含「给客户交付」。拿不准就问作者。
3. **席位** ≥ 实际人数。页面显示「不限」的，人数不受限制。
4. **到期日**：页面显示「永久」就是长期有效；到期日当天仍然有效，第二天起算过期。页面按这台电脑的本地日期算，电脑日期不对，结果会跟着错。
5. **授权码编号**：记下来，和合同、付款记录一起存档。

## 四、几件要知道的事

- 授权码就是一串文字，谁都能复制。拿到别人的码，不等于你们有授权，所以第三步一定要做。
- 核验页和命令行只验签名，不查作废名单。授权码可能因为退款、泄露或冒用被作废，规则见官方仓库的 `COMMERCIAL-LICENSE.md`。想确认没被作废，就发邮件问作者。
- 拿不准的时候发邮件给作者，附上授权码编号、合同或付款记录。联系方式以官方仓库 `COMMERCIAL-LICENSE.md` 里写的为准。
